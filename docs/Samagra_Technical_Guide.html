1Samagra in one picture

What is Samagra, technically?

In shortOne Python web application. Browsers talk to it; inside it, business rules do the work, AI agents only read documents, and everything is stored in a database plus a folder of files. For email, prices and AI it calls three outside services.
 USERS & SOURCES            SAMAGRA  (one Python program)                       OUTSIDE
 ───────────────            ──────────────────────────────                      ───────
 Requester ──┐              Uvicorn  listens on port 8000
 GP buyer  ──┼─ browser ──▶ FastAPI  address → Python function
 GP head   ──┘                │
                              ├─ WEB LAYER      login & roles · ~60 routes · Jinja2 pages
 Supplier ── token link ────▶ │                                                  ──▶ SerpAPI
   (through Cloudflare tunnel)├─ DOMAIN RULES   intake parser · comparison ·         (prices)

                              │                 supplier RFQ · notifications         (mail in & out)
                              ├─ AI AGENTS      offer · enquiry · ask this case  ──▶ LLM
                              │  (read only)    — all through one gateway, llm.py    (LLMaaS / Ollama)
                              └─ DATA           SQLite (16 tables) + file store      SAP (proposed)

The sentence to remember: "The model reads, the code decides, a person approves." AI turns messy documents into data; ordinary code does every calculation and check; every decision is a person's click.

Terms
Web application
A program on a server that people use through a browser, without installing anything.
Monolith
One program containing the whole application, as opposed to many small programs (microservices) talking over the network.
Layered
Code organised in levels (web, rules, AI, data); each level uses the one below it.
Server
The computer (or program) that answers requests. Today: the demo laptop.

Why one program and not microservices?

In shortBecause 600 cases a year doesn't need them. One program is simpler to run, test and secure; the layers inside keep it organised, so a part can be split out later if it ever needs to be.

Microservices pay off when different parts must scale separately or are owned by different teams. Here one small team owns everything and the load is light. Splitting would add network calls between services, separate deployments and more places to fail, without a benefit. The layered design means the price check, for example, could become its own service later without rewriting the rest.

Terms
Microservices
An architecture where each function is a separate program with its own deployment, talking to the others over HTTP.
Deployment
Putting a version of the software onto the server where people use it.

2The architecture, block by block

Every box on the architecture slide, left to right and top to bottom: what it is, why it is there, and where it lives in the code.

Users and sources (left column)

Requester

In shortThe VW employee who needs something bought. They float enquiries to suppliers, then raise the sourcing request with all documents, and answer the buyer's questions.

Uses the browser, signed in. Sees only their own requests and enquiries. The request form refuses to submit until the required documents are attached and the InfoSec questions are answered.

In the coderouters/requester_routes.py (request form, my requests, reply), the enquiry half of routers/supplier_routes.py, validators.py (what makes a request complete), templates in templates/requester/.

GP buyer

In shortThe Procurement person. Receives complete cases routed by commodity, checks the documents, compares offers, checks market prices, asks questions, and approves with a PO number.

Only the buyer a case is assigned to can act on it; others can "take over", which is logged. Commodities are split between buyers in configuration: for example tablets and printers go to Sayali, headsets and AV to Vikas, UPS to Nilesh.

The head manages the team on the Team page: adds buyers, sets which commodities each owns, and marks a buyer on leave so new cases go to a cover (optionally moving their open cases, each logged).

In the coderouters/buyer_routes.py (queue, case page, every buyer action), config.py (buyer_for_commodity, leave cover), team.py and routers/team_routes.py (Team page), templates in templates/buyer/.

GP head

In shortThe manager. Sees dashboards: open cases, TAT performance, workload per buyer, spend per department, single sourcing, with Excel export.
In the codedashboard.py (the numbers), dashboard_export.py (Excel), static/js/dashboard-admin.js and dashboard-buyer.js (charts), templates/buyer/dashboard_admin.html.

Supplier: token link through the tunnel

In shortAn outside company with no account. They get an email with a private link containing a long random token; the page lets them download the RFQ and quote, revise or decline until the deadline.

The laptop is not on the internet, so the Cloudflare tunnel gives it a public address for the demo. In production this becomes VW's own internet gateway (see Scaling).

In the codethe bottom half of routers/supplier_routes.py (routes /rfq/{token}), supplier_rfq.py, templates/supplier/rfq_portal.html.
Terms
Token
A long random string that works as a key: whoever has the link can open that one page.
Tunnel
A connection that carries internet traffic to a machine that is otherwise unreachable.

GP mailbox

In shortRequests that arrive by email. A buyer clicks "Check mailbox now"; Samagra reads the inbox through Microsoft Graph, identifies cart, SFO, RFQ and offers in the attachments, and proposes a case for the buyer to confirm.

Nothing runs in the background and nothing is created without a person confirming.

In the codemailbox.py (reading the inbox via Graph), mailbox_intake.py and extraction.py (turning a mail into case fields), mailbox_staging.py, routers/mailbox_routes.py.

The Samagra box: FastAPI on Uvicorn, one Python process

Web layer: Auth & roles

In shortLogin, and checking on every request who you are and what you may do. A signed cookie remembers you; your role comes from your email address.

After login the browser stores a session cookie holding your email, signed with a server secret so it can't be forged. Before each page, a dependency such as require_buyer reads it: not logged in → login page; wrong role → "403 not allowed".

In the coderouters/auth_routes.py, security.py (password hashing), deps.py (require_login, require_buyer, require_requester), session set-up in main.py.

Domain rules: Intake parser

In shortReads uploaded carts and quotations (PDF, Word, Excel) and pulls out the item table: description, quantity, unit price, total. If the table can't be read, the AI reads it and every figure is checked against the text.

Form autofill: when the requester attaches documents, the request form fills its empty fields from them: SC number, department, cost center, title, description, commodity, delivery location, value, currency and tax basis, from the cart, or for a frame contract from the SFO and RFQ. Each filled field says which document it came from; nothing the requester typed is overwritten; MRM, InfoSec and who the request is for are never filled, because they are the requester's own declarations. Tested on 33 document sets: 290 values right, none wrong, uncertain ones left blank.

In the codeparser.py (tables and text from PDF/Word/Excel), extraction.py, prefill.py and static/js/prefill.js (form autofill), validators.py, vision.py (scans; switched off).

Domain rules: Comparison

In shortPuts all quotations on one basis before ranking: removes GST where a quote includes it, converts currencies, then ranks. A quote that prints a higher number can rank cheaper.
In the codecomparison.py, quotation_check.py (does the quote cover what was asked, what's missing), rate_sheet*.py (the Rate Comparison Excel buyers already use).

Domain rules: Market check

In shortFor catalogue products, searches Amazon.in and Google Shopping India, keeps trusted sellers and the same product only, and shows each supplier's price against the market.

Filters drop used, refurbished, foreign, accessories and spare parts; model numbers must match as whole words; required specs (RAM, storage) must be present. The AI judges "same product?" and code makes the final call.

In the codebenchmark.py, the panel templates/buyer/_tabs/_market_check.html.

Domain rules: TAT & advisor

In shortTAT counts working days from the day the documents were complete: 15 days up to ₹3.5 lakh, 30 up to ₹40 lakh. The advisor reads the case's facts and recommends the one next action, with reasons.
In the codetat.py, agents/advisor.py, handover.py ("Ready to award?").
Terms
TAT
Turnaround time: the working days GP commits to for closing a case.

Domain rules: Supplier RFQ

In shortCreates an enquiry ("round"), a private link per supplier, records each reply, and keeps every version of every quotation (v1, v2, v3). Deadlines close and reopen the links.
In the codesupplier_rfq.py, routers/supplier_routes.py.

Domain rules: Notifications

In shortEvery email Samagra sends (case submitted, question asked, approved, enquiry to suppliers, deadline extended) plus the in-app messages. Mail goes out through Microsoft Graph.
In the codenotifications.py (what to send), mailbox.py → send_via_graph (how).

AI agents: read, never decide

In shortThree agents follow a logged perceive → decide → act cycle. The Offer agent and the Enquiry agent use AI to read or draft. The Advisor uses only rules. A fourth AI feature, Ask this case, answers questions from a case's documents.

Details in the AI chapter. All model calls go through one gateway, llm.py.

In the codeagents/base.py, agents/offer.py, agents/enquiry.py, agents/advisor.py, ask_case.py, llm.py.

Data: SQLite and the file store

In shortOne database file (sourceflow.db, 16 tables) holds every fact and the audit trail; the documents themselves are files in folders, one per case and one per enquiry.
In the codedb.py is the only file that talks to the database. Files: repository/ (cases), rfq_rounds/ (enquiries), mailbox_staging/, drafts_staging/.

Right column: deployment and external services

Deployment box

In shortToday: one process on the demo laptop. Next: the same code packaged as a container on VW's cloud, with a fixed address.

SerpAPI, Microsoft Graph, LLM, SAP

In shortSerpAPI returns shopping search results for the market check. Microsoft Graph sends all mail and reads the intake inbox. The LLM is VW LLMaaS GPT-4o, with Ollama on the laptop as fallback. SAP is proposed, not built.

3Starting it: .\run.ps1 -Tunnel

What does .\run.ps1 -Tunnel do?

In shortIt is a start-up script that does five things in order: frees port 8000, opens the public tunnel and saves its address, makes sure the local AI is running, checks every feature, and starts the server.
  1. Frees port 8000. Stops any old Samagra still listening there; if it can't, it uses the next free port.
  2. Opens the tunnel (only with -Tunnel). Starts cloudflared.exe from your Downloads folder, waits for it to print its public address (https://….trycloudflare.com) and writes that address into public_url.txt. Samagra reads this file whenever it builds a supplier link.
  3. Starts Ollama if it isn't running, so the local AI model is there as a fallback.
  4. Runs the readiness check tools/demo_check.py: database, AI model, email, price search, supplier links. If VW LLMaaS isn't reachable (VPN off), this run switches to the local model.
  5. Starts the server: uvicorn main:app --host 127.0.0.1 --port 8000.

Without -Tunnel, step 2 is skipped and supplier links point to localhost, which only works on your own laptop.

Remember: the tunnel address changes on every start, and dies if the laptop sleeps or the network changes. Start it shortly before the demo, then send enquiries. Python code changes need a restart; template changes don't.
In the coderun.ps1 (the script), public_url.txt (the address, written by the script), config.py (reads it), supplier_rfq.portal_link (builds each supplier link from it), tools/demo_check.py.

What does uvicorn main:app --host 127.0.0.1 --port 8000 mean, word by word?

In short"Uvicorn, take the object called app from the file main.py, and answer requests arriving at this computer on door 8000."
  • uvicorn: the server program that receives web requests.
  • main:app: file main.py, object app (the FastAPI application created there).
  • --host 127.0.0.1: accept requests only from this same computer. Outside visitors come in through the tunnel, which runs on the laptop.
  • --port 8000: the numbered door to listen on.

Why not python main.py? main.py only defines the application; it doesn't listen on the network. Uvicorn is what makes it reachable.

Terms
Script (PowerShell)
A text file of commands Windows runs in order. .ps1 is a PowerShell script.
Port
A numbered "door" on a computer so several network programs can run side by side. 8000 is Samagra; 11434 is Ollama.
127.0.0.1 / localhost
The address meaning "this same computer".
Process
One running copy of a program.
Ollama
A program that runs open AI models on your own computer.
cloudflared
Cloudflare's small program that creates the tunnel.

4What happens while it runs

A user clicks something. What happens, step by step?

In shortThe browser sends a request; Uvicorn receives it; FastAPI finds the function for that address; the login check runs; the function reads or writes the database and applies the rules; Jinja2 fills the page; the finished page goes back.

Example: a buyer opens case 57.

Browser:  GET /queue/57
   │
Uvicorn   receives it on port 8000
   │
FastAPI   finds the function queue_detail() in routers/buyer_routes.py
   │
deps.py   require_buyer: reads the session cookie → logged in? a buyer?   no → login page / 403
   │ yes
buyer_routes.queue_detail()
   ├── db.py            reads the case, documents, audit trail from sourceflow.db
   ├── tat.py           working days left on the clock
   ├── agents/advisor   next action and alerts (rules only)
   ▼
Jinja2    fills templates/buyer/queue_detail.html with that data
   │
Browser   receives finished HTML, applies CSS, runs JavaScript for tabs and buttons

An ordinary page takes milliseconds. Pages that wait on the AI ("Ask this case", offer analysis, market check) take seconds to a minute, because the model is reading documents.

What happens in the background, without anyone clicking?

In shortOnly one thing: when a supplier uploads a quotation, the Offer agent starts by itself in a background thread and prepares the comparison. There is no scheduler and no polling.

At start-up the app also creates or updates the database tables and removes expired form drafts (main.py → lifespan). Everything else happens because a person clicked.

In the codesupplier_rfq._fire_offer_agent (the background thread), main.py (start-up).
Terms
Thread
A separate line of work inside a running program, so slow work doesn't make the user wait.
Scheduler / polling
Code that runs on a timer, e.g. "check the inbox every 5 minutes". Samagra has none.

5Frontend

What is the frontend made of?

In shortHTML pages built on the server with Jinja2, styled with CSS, with plain JavaScript for interactions and Chart.js for the charts. No React, no build step.
  • 41 HTML templates in templates/: an HTML file with gaps like {{ case.topic_title }}, which Python fills.
  • 16 CSS files in static/css/: colours, fonts, spacing, the teal look. base.css holds the shared parts.
  • 19 JavaScript files in static/js/, one job each: switching tabs, showing or hiding form fields, drag-and-drop uploads, the InfoSec popup, busy buttons, the dashboards.
  • Chart.js (charts) and SheetJS (Excel in the browser) stored in static/js/vendor/, so they work without internet.
Terms
Frontend
Everything the browser shows and runs.
HTML / CSS / JavaScript
Page structure / page looks / programs the browser runs.
Template / Jinja2
An HTML file with placeholders; Jinja2 is the Python tool that fills them.
Build step
Compiling and bundling frontend code (npm, Webpack) before it can run. We have none.

What does "server-rendered" mean, and how is the logic "all in Python"?

In shortPython decides what to show and fills it into the HTML before sending. The browser receives a finished page. HTML and CSS only describe the look; JavaScript only adds clicks after the page arrives.
# routers/requester_routes.py — Python fetches the data
cases = db.list_cases({"requestor_email": user["email"]})
return templates.TemplateResponse(request, "requester/my_requests_list.html", {"cases": cases})

<!-- templates/requester/my_requests_list.html — Jinja2 fills the gaps -->
{% for c in cases %}
  <tr><td>{{ c.topic_title }}</td><td>{{ c | money }}</td></tr>
{% endfor %}

If you open "View source" in the browser, you see real text, no {{ }}: it was filled on the server.

Why not React, Angular or Vue?

In shortSamagra is forms, tables and case pages. React would mean a second codebase in a second language, a build pipeline and an API between the two, for no gain. Server pages keep one language and load fast.
  • React / Angular / Vue build the page inside the browser: the server sends a JavaScript program and raw data, and the program draws the screen. That suits very interactive apps (design tools, chat, live boards).
  • For us that would mean: logic split across Python and JavaScript, a JSON API for every screen, npm and a build step, and slower first load.
  • Where we need live behaviour (Ask this case, the market check, the dashboards), a small JavaScript file calls the server in the background and updates part of the page.

If VW later wanted a mobile app or a highly interactive screen, the same backend functions could be offered as a JSON API and React used for that part only.

Terms
React / Angular / Vue
Popular JavaScript frameworks that build pages in the browser.
SPA (single-page application)
A site where one big JavaScript program draws every screen.
API
Addresses a program calls to get or send data, usually as JSON.
npm
JavaScript's package manager, used to install and build React projects.

Why not Streamlit? Didn't we start with it?

In shortYes. Samagra started on Streamlit, a quick tool for data apps. The challenge owner didn't like its look, and it can't do proper multi-user pages, roles or custom layouts. We rebuilt the pages on FastAPI and kept all the business logic.
Terms
Streamlit
A Python library for quick data dashboards; every page reruns the whole script on each click.

How do the browser and the server talk?

In shortNormal links and forms (GET and POST) return whole pages. A few live actions call the server in the background with fetch() and get JSON back. All of it is HTTP, and HTTPS through the tunnel.
Terms
HTTP / HTTPS
The language browsers and servers speak; HTTPS is the encrypted version.
GET / POST
"Show me a page" / "here is data, act on it".
fetch()
The JavaScript command to call the server without reloading the page.

6Backend

What is the backend?

In shortPython with the FastAPI framework, run by the Uvicorn server. About 60 routes in 8 router files call the business rules, the AI gateway and the database.
Terms
Backend
The program on the server: data, rules, secrets.
Framework
A ready-made toolkit that handles web plumbing so you write only your own logic.
FastAPI
A modern Python web framework: maps addresses to functions, checks access, validates input, supports async.
Uvicorn
The server program that listens on the network and hands each request to FastAPI.

Why Python?

In shortIt has the strongest tools for the two hard parts of this problem: reading documents (PDF, Word, Excel) and working with AI models. Java or Node.js are weaker at both.

Libraries used: pdfplumber (PDF tables and text), python-docx (Word), openpyxl (Excel), fpdf2 (creating PDFs), httpx (calling outside services), msal (Microsoft login), numpy (working-day counting), truststore (uses Windows certificates so HTTPS works on the VW VPN).

Why FastAPI, and not Django or Flask?

In shortDjango is heavy and brings a database layer and admin panel we didn't need. Flask would work but needs add-ons for access checks, validation and async. FastAPI has all three built in and is modern and fast.
OptionWhat it isWhy not for Samagra
Django"Batteries included": its own ORM, admin site, templates, authHeavy and opinionated; we wanted plain SQL in one file and our own small auth. Fine choice for a bigger team, more than this needs.
FlaskMinimal framework: routes and templatesWould work. Access checks, form validation and async calls need extra libraries; FastAPI has them built in.
Node.js / ExpressJavaScript on the serverWeaker libraries for PDF/Word/Excel and AI work.
Java Spring / .NETEnterprise frameworksMuch more code for the same result; slower to build in a hackathon window.
FastAPIModern Python frameworkChosen: dependencies for access control (require_buyer), input validation, async for slow calls, automatic API documentation if we add an API.
Terms
ORM
Object-relational mapper: writes SQL for you from Python classes. We use plain SQL instead, all in db.py.
Dependency (FastAPI)
A function FastAPI runs before a route, e.g. "is this user a buyer?".
Async
Code that can wait on something slow without holding everything else up (only if the slow call itself is async; see Known gaps).

Why Uvicorn?

In shortFastAPI defines the answers but can't listen on the network itself; Uvicorn is its standard server. In production it runs several copies (workers) behind a gateway.
Terms
ASGI server
The kind of server that runs async Python web apps. Uvicorn is one; Gunicorn can manage several Uvicorn workers.
Worker
One extra copy of the server process, so requests are served in parallel.

How is the backend code organised?

In shortStart-up in main.py; web layer in routers/, deps.py, security.py; rules in their own modules; AI in llm.py and agents/; all data access in db.py; all settings in config.py.

Why SQLite today?

In shortZero set-up, zero administration, backups are a file copy, and it easily handles GP India's volume: 41 cases use 660 KB. It runs in WAL mode so reads aren't blocked by writes.
Terms
WAL (write-ahead logging)
A SQLite mode where changes go to a log first, so people can keep reading while someone writes.

Why PostgreSQL for production, and not MySQL, SQL Server, Oracle or MongoDB?

In shortPostgres is a free, full database server that handles many users writing at once, and it supports two things we already rely on: storing JSON and partial unique indexes (our "one PO, one case" rule). If VW IT standardises on another relational database, the same move works.
OptionVerdict
PostgreSQLFirst choice. Open source, no licence; many simultaneous writers; strong JSON support (our comparisons and market checks are stored as JSON); partial unique indexes like ours; offered as a managed service on every major cloud.
MySQL / MariaDBWould work. Weaker JSON querying and no partial indexes, so the PO rule would need rewriting.
SQL Server / OracleFine if VW IT prefers them; licence costs. Because all SQL is standard and in one file, the move is the same effort.
MongoDBNot a fit. Our data is relational (case → documents → line items → audit) and needs joins and transactions. A document database would push that work into our code.

What the move involves: change the connection in db.py, adjust a few SQLite-specific statements, copy the data across, and use Postgres's own backups.

Terms
PostgreSQL (Postgres)
A free, full database server used widely in enterprises.
Relational
Data in related tables (a case has many documents) joined by IDs.
Partial unique index
A rule like "PO number must be unique, but only when it's filled in".
Transaction
A group of changes that all succeed or all fail together.
Managed database
A database run by the cloud provider or IT, who handle backups, updates and failover.

What happens when the data grows?

In shortSize isn't the risk: ten years of GP India is roughly 100 MB of database. Query speed is, and that is solved with indexes, summary tables and archiving. Documents grow faster and move to object storage.
VolumeDatabaseDocuments (estimate, 1–10 MB per case)
GP India, 600 cases/year~10 MB a year~0.6–6 GB a year
Ten years~100 MB~6–60 GB
  • Indexes on status, buyer and dates keep searches fast at millions of rows.
  • Summary tables per month keep dashboards fast over years of data.
  • Archiving moves closed cases older than the retention period to cheaper storage, still searchable.
Careful: document sizes are an estimate; the pilot measures them.
Terms
Index
A sorted lookup, like a book's index, so the database finds rows without reading everything.
Archiving
Moving old records out of the busy tables, without deleting them.

8AI and the agents

Where is AI used, and where not?

In shortOnly for reading and drafting: quotations, odd carts, emailed requests, whether a quote covers the RFQ, whether a listing is the same product, the supplier note, and Ask this case. Every calculation, check and decision is ordinary code or a person.

Not AI: tax stripping, currency conversion, ranking, TAT, the next-action advisor, document completeness, duplicate checks, InfoSec rules.

What are the three agents?

In shortCode that starts on an event, follows perceive → decide → act, and logs every run. The Offer agent reads and ranks quotations; the Enquiry agent drafts the supplier note from the RFQ; the Advisor recommends the next step using rules only.
AgentAI?Starts whenDoes

Software that acts by itself in response to an event and records what it did.

How do you stop the AI from inventing numbers?

In shortEvery figure the model returns must appear in the document text, or it is discarded or marked "[to confirm]". The model answers in a fixed JSON format, at low temperature, and never makes a decision.
  1. Verification: numbers checked against the document's own digits; quantities in a supplier note checked against the RFQ.
  2. Grounding: Ask this case only sees that case's documents and must say when something isn't there.
  3. Structured output: fixed JSON fields, read by code.
  4. Temperature 0: the same document always gives the same reading (changed from 0.2 on the technical jury's advice).
  5. No decisions: a person approves everything.
Terms
LLM
Large language model: AI trained on huge amounts of text that can read and write, e.g. GPT-4o.
Hallucination
A model stating something confidently that isn't true or isn't in its source.
Temperature
How random the model's wording is; low = consistent.

Which model, and why two?

In shortVW LLMaaS with GPT-4o is the approved, best-quality model. Ollama running Qwen 2.5 7B on the laptop is a free, offline fallback. One setting, LLM_MODE, switches; the code is the same.

Both accept the same OpenAI-style request, so llm.py sends the same thing to either. LLMaaS needs the VPN and the team's credentials (environment variables, never in code); usage is capped, so rehearsals use the local model.

Terms
LLMaaS
"LLM as a service": VW's internal platform offering approved AI models.
Ollama / Qwen 2.5 7B
Ollama runs models locally; Qwen 2.5 7B is an open model with 7 billion parameters.

Why no LangChain, RAG, vector database or fine-tuning?

In shortNot needed. Each question is about one case whose documents fit in the model's input, so we pass them whole. A thin gateway of our own (llm.py) gives full control over verification with fewer dependencies.
  • LangChain: a framework for chaining AI calls. Adds a large dependency for something we do in a few functions.
  • RAG / vector database: for searching thousands of documents. Useful later for "what did we pay before?" across past cases.
  • Fine-tuning: retraining a model on our data. Not needed for reading, and it would put VW data into a model.
Terms
RAG
Retrieval-augmented generation: search first, then give the AI only the relevant passages.
Vector database / embeddings
Text turned into numbers so similar meanings can be searched.
Fine-tuning
Training an existing model further on your own data.

9Microsoft Graph and email

What is Microsoft Graph?

In shortMicrosoft's official API for Outlook, Teams, OneDrive and the rest of Microsoft 365. Samagra uses it to send every email and to read the intake mailbox, over normal HTTPS.

Instead of talking to a mail server in the old way, Samagra calls web addresses such as https://graph.microsoft.com/v1.0/me/sendMail, with a permission token, and Microsoft sends the mail from that mailbox.

Terms
API
Web addresses a program calls to do something, here: send a mail, list the inbox.
Microsoft 365
Microsoft's cloud office suite: Outlook, Teams, OneDrive, SharePoint.

Why Graph and not SMTP?

In shortWe started on SMTP, but the VW network blocks SMTP's ports. Graph works over normal HTTPS, which isn't blocked, and it's Microsoft's own recommended way. The SMTP code is still there, unused.
  • SMTP is the traditional mail-sending protocol, on ports 465/587 that corporate firewalls often block.
  • Graph uses port 443 (HTTPS), the same as every website, and modern login (OAuth) instead of a stored mailbox password.
  • Alternatives like SendGrid or Mailgun are outside services: our mails would pass through a third party. VW already works in Microsoft Outlook and Teams, so Graph keeps mail within Microsoft.
Terms
SMTP
Simple Mail Transfer Protocol, the classic way programs send email.
Firewall
A network filter that blocks certain traffic, e.g. some ports.

How does Samagra log in to the mailbox?

In shortOnce, a person signs in with a code on Microsoft's page (device-code login). Samagra keeps the resulting refresh token in a local file and from then on gets fresh access silently. No password is stored.
  1. The app is registered in Microsoft Entra (Azure) with permissions Mail.Read and Mail.Send.
  2. scripts/mailbox_login.py shows a code; a person enters it at microsoft.com/devicelogin and signs in to procurement.intake.demo@outlook.com.
  3. The MSAL library saves a refresh token in a cache file. Every later mail uses it to get a short-lived access token, with no browser.

Production would use VW's own shared mailbox and an app registration in VW's tenant, approved by VW IT.

In the codemailbox.py (MSAL login, send_via_graph, check_mailbox), notifications.py (chooses SMTP if configured, otherwise Graph), scripts/mailbox_login.py.
Terms
OAuth
A standard that lets an app act for an account with time-limited tokens instead of its password.
MSAL
Microsoft Authentication Library: the official code for getting those tokens.
Access / refresh token
A short-lived pass (about an hour) / a longer-lived pass used to get new access tokens.
Entra ID (Azure AD)
Microsoft's identity service where apps are registered and permissions granted.
Tenant
An organisation's own space in Microsoft's cloud, e.g. VW's.

What exactly does Samagra do with Graph?

In shortTwo things: send mail (with attachments up to Graph's 3 MB limit, which Samagra checks first) and, when a buyer clicks, read new mails and their attachments from the inbox.

10Price search and the tunnel

Why SerpAPI for prices?

In shortSerpAPI runs a Google Shopping or Amazon search and returns the results as clean data. It's legal and stable; scraping websites breaks often and breaks their terms.

Per catalogue item: Google Shopping India twice, Amazon.in once. Free plan: 250 searches a month. Results are reused for 24 hours per case. Alternatives: Amazon's Product Advertising API requires an affiliate account with sales; scraping is fragile and not allowed.

Terms
Scraping
A program reading a website's pages directly and pulling data out of the HTML.
Quota
The number of calls a plan allows per month.

What is the Cloudflare tunnel, and why not ngrok?

In shortIt gives the laptop a temporary public web address so suppliers anywhere can open their link. Cloudflare's quick tunnel needs no account; ngrok's free plan shows visitors a warning page first. Both disappear in production.

cloudflared opens an outgoing connection from the laptop to Cloudflare; visitors reach Cloudflare's address and the traffic comes back through that connection. Nothing on the laptop is opened to the internet directly. The address changes every start and dies if the connection drops.

At VW scale the tunnel goes away: Samagra runs on VW servers with a fixed address, staff use it on the intranet, and only the supplier pages (/rfq/…) are published through VW's internet gateway.

Terms
DNS
The internet's address book that turns a name into a server's number. A dead tunnel's name no longer exists there.
Gateway / reverse proxy
A server at the network edge that lets only allowed outside requests in.
Intranet
The company-internal network.

11Security

How are logins and passwords protected?

In shortPasswords are stored only as salted PBKDF2 hashes (200,000 rounds). A signed session cookie lasts 12 hours. Your role is re-checked on every request. Production replaces passwords with VW single sign-on.
In the codesecurity.py, deps.py, routers/auth_routes.py, session settings in main.py and config.py.
Terms
Hash
A one-way scramble: a password can be checked against it but not recovered.
Salt
Random data added per user, so equal passwords give different hashes.
PBKDF2
A standard, deliberately slow hashing method that makes guessing expensive.
SSO
Single sign-on: logging in once with the company account for every app.

How is the supplier link secure without a login?

In shortEach supplier gets its own 32-byte random token per enquiry. It opens only that supplier's page, stops at the deadline, and reveals nothing if guessed wrong. Staff who open it see a preview and can't answer.

Who sees what?

In shortRequesters see only their own requests and enquiries; buyers see the queue but act only on cases assigned to them; suppliers see one page each. Every action is in the audit trail.
Terms
RBAC
Role-based access control: permissions by role.

Where are keys and secrets kept?

In shortIn environment variables on the server, never in code or the browser. Production would use a secrets vault.
Careful: set SOURCEFLOW_SESSION_SECRET on the demo machine; without it the code falls back to a default written in the source.
Terms
Environment variable
A named setting given to a program by the operating system, outside its code.
Secrets vault
A secure service to store and rotate keys, e.g. Azure Key Vault.

What is "VW object storage"?

In shortA cloud service for storing files by key instead of in a folder on one server, like Amazon S3 or Azure Blob Storage. "VW object storage" means whichever such service VW IT provides.

Every app copy can reach the same files; the provider keeps several copies so nothing is lost; it grows without limit and has access control, encryption and versioning built in. Code impact is small: the database already stores only a path per file, so only saving and reading change.
